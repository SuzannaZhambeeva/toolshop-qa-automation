# Toolshop QA Automation

Демо-проект автоматизации тестирования интернет-магазина
[Practice Software Testing (Toolshop)](https://practicesoftwaretesting.com).

## Стек

- Python, pytest
- requests, jsonschema — API-тесты
- Playwright — UI-тесты (Page Object Model)
- Allure — отчёты
- GitHub Actions — CI

## Установка и запуск

### 1. Клонировать репозиторий

```bash
git clone https://github.com/SuzannaZhambeeva/toolshop-qa-automation.git
cd toolshop-qa-automation
```

### 2. Создать и включить виртуальное окружение

Создать (один раз):

```bash
python3 -m venv venv
```

Включить (каждый раз при открытии нового терминала):

```bash
# macOS / Linux
source venv/bin/activate

# Windows
venv\Scripts\activate
```

Выключить:

```bash
deactivate
```

### 3. Установить зависимости

Тесты не запустятся без библиотек из `requirements.txt`.
Устанавливать нужно при включённом виртуальном окружении:

```bash
pip install -r requirements.txt
```

Для UI-тестов дополнительно нужен браузер

```bash
playwright install chromium
```

### 4. Настроить переменные окружения

Скопировать шаблон адресов и учетных данных:

```bash
cp .env.example .env
```
Затем вписать в .env email и пароль тестового пользователя


### 5. Запустить тесты

```bash
pytest                  # все тесты
pytest tests/api        # только API-тесты
pytest tests/ui         # только UI-тесты
pytest -m smoke         # только smoke-тесты
pytest -m regression    # полный регресс
```

## Подсказки: как закоммитить правки в GitHub

### 1. Посмотреть, что изменилось

```bash
git status
```

Красным показаны изменённые файлы, которые ещё не добавлены в коммит,
зелёным — уже добавленные.

### 2. Добавить файлы в коммит

```bash
git add README.md          # один конкретный файл
git add .                  # все изменённые файлы
```


### 3. Сделать коммит

```bash
git commit -m "Короткое описание изменений"
```


### 4. Отправить на GitHub

```bash
git push
```

### 5. Забрать свежие изменения с GitHub

Если правки делались на другом компьютере или прямо на сайте GitHub:

```bash
git pull
```

### Полезное

```bash
git log --oneline          # история коммитов, по одной строке
git diff                   # что именно изменилось в файлах (до git add)
git restore README.md      # отменить несохранённые правки в файле
```

Если в шапке вывода pytest указан путь не к `venv`, а к системному Python,
значит терминал запускает глобальный pytest. Решение:

```bash
hash -r            # сбросить кэш путей к командам в терминале
python -m pytest   # или запускать pytest через активный Python
```

## Что покрыто тестами

### API

**Товары** (`tests/api/test_products.py`)
- Получение списка товаров
- Получение товара по id
- Запрос несуществующего товара (404)
- Пагинация: вторая страница отличается от первой
- Соответствие ответа JSON-схеме (обязательные поля, типы, ограничения)

**Авторизация** (`tests/api/test_auth.py`)
- Успешный логин и получение токена
- Доступ к профилю с токеном и без токена (401)
- Негативные сценарии логина (параметризованный тест): неверный пароль,
  несуществующий email, пустые поля, неверный формат email

### Наблюдения

- Неверный пароль и несуществующий email возвращают одинаковый ответ —
  API не раскрывает, какие пользователи зарегистрированы.
- Пустые email/пароль возвращают `401` с текстом `Invalid login request`;
  для ошибок валидации обычно используют `400`/`422` — требует уточнения.
- Ошибки авторизации приходят в разном формате:
  `{"error": ...}` при логине и `{"message": ...}` при запросе профиля.
- Запрос страницы за пределами диапазона возвращает `200` и пустой список.
